| 1 | Outcome proposal retry bug: a failed or crashed `proposeOutcome` could be lost or double-sent (P0) | **Fixed** | Durable outbox + state machine `EVALUATED → PROPOSAL_PENDING → PROPOSAL_BROADCAST → PROPOSED_ONCHAIN → (CHALLENGED) → FINALIZED` (migration `009_outcome_proposals.sql`, `apps/api/src/workers/outcomes.ts`). Stages are derived from the chain (`apps/api/src/lib/paytx.ts`, table `payment_txs`), exposed by `/pay/intents/:id/tx`, `/pay/tx/:hash`, `/auth/connect/handoff/tx` (now with `stage`, `paid`) and `/auth/connect/handoff/tx-status`, MCP `atlas_connect_tx_status` (tool texts forbid calling it paid before `paid:true`). Web stepper in the send sheet, Connect handoff and receipts. Browser wallet and the companion send the pay step only after the approval is mined. Tests: `packages/auth/test/pay-status.test.ts`, `apps/api/test/pay-lifecycle.test.ts` (anvil: delayed receipt, duplicate report, replaced tx, mismatched tx, approve step), companion tests, connect tests. |
